# MergeBoard

MergeBoard 是一个基于 **Cocos Creator 3.8.8** 和 TypeScript 的合并棋盘游戏练习项目，也用于客户端开发笔试实践。玩家在棋盘上拖动物品、交换位置或合成升级，并可点击固定生成器获得新物品。项目包含本地棋盘存档和重新进入后的状态恢复。

## 当前版本与功能状态

当前基础版本 **v1.0.0 已发布**（由用户确认）。本 README 不记录未经核实的 tag、Release 链接或推送细节。

**当前工作阶段：**完成 Web 构建和 Android APK 可运行包。两种目标的构建配置、实际构建结果及运行验收状态需在对应环境中单独确认。

### 已实现并经用户人工测试

以下基础功能由用户报告在 Cocos Creator 预览中手动验证通过：

- 7 列 × 9 行棋盘及物品贴图显示正常。
- 普通物品可以拖到空格；拖出棋盘边界后回到原位。
- 同等级物品可以合成，不同等级物品可以交换。
- 固定生成器显示正常，点击可生成一级物品；连续生成不覆盖已有物品。
- 普通物品不能覆盖生成器；棋盘满时生成失败且不覆盖现有物品。
- 生成器生成的物品可以参与合成。
- 关闭浏览器预览后重新启动，可以恢复上次的物品数量、等级和位置；恢复后生成器仍存在并可点击。

### 尚未完成或尚未验证

- TypeScript 编译和类型检查尚未验证。
- `createItem()` 返回 `null` 或抛出异常时的恢复清理、损坏/非法存档的运行时回退尚未实测；异常注入用例需要测试专用手段。
- 生成、移动、交换、合成四类操作各自保存后分别关闭重启的独立验收尚未完成；当前只有用户报告的整体关闭/重启恢复结果。
- 下文列出的六项进阶需求均为计划开发，不属于当前已实现功能。

项目目前有用户人工测试记录，但没有声称通过完整自动化测试。测试状态和用例见[测试用例](docs/TEST_CASES.md)及[边界情况说明](docs/EDGE_CASES.md)。

## 环境要求与运行

- Windows 开发环境。
- Cocos Creator **3.8.8**。项目根目录的 `package.json` 声明 Creator 版本为 3.8.8。
- TypeScript 脚本由 Cocos Creator 项目环境处理。根目录 `package.json` 当前没有定义 npm 运行脚本。

### 打开项目和预览

1. 启动 Cocos Creator 3.8.8，在其项目选择/打开现有项目流程中选择本项目根目录。根目录应同时包含 `package.json` 和 `assets/`；打开已有目录，不要新建替代工程。
2. 在编辑器资源面板中进入 `assets/Scene/`，打开 `Main.scene`。目录名大小写为 `Scene`。
3. 使用编辑器工具栏中的预览/运行控制启动主场景。Creator 的具体按钮文字和预览目标会随当前编辑器界面设置变化；本说明不假定某个未核实的菜单名称。
4. 在预览中拖动物品或点击生成器进行交互。若检查存档恢复，请关闭并重新打开同一预览来源，保持相同的浏览器配置文件、origin 和站点存储上下文。清除站点数据、更换浏览器或更换 origin 后，本地存档不保证仍可访问。

主场景路径已由当前项目文件确认。此 README 不声称本次编写文档时执行了预览或编译。

### 核心脚本职责

- **`BoardConfig.ts`**：定义 `COLS = 7`、`ROWS = 9`、单格尺寸、`MAX_LEVEL = 12`，并在网格坐标与棋盘本地坐标之间转换。
- **`CellView.ts`**：记录单格的列/行，确保 `UITransform` 尺寸，并使用可选 Sprite 或 `Graphics` 绘制底格。
- **`BoardView.ts`**：创建格子、物品容器和固定生成器；以 `_items[col][row]` 保存普通物品引用；处理创建、移动、交换、合成、生成器点击及存档读写/校验/恢复。
- **`ItemView.ts`**：保存单件物品的 `itemType`、`level`、`col`、`row`，设置尺寸和等级贴图，并处理拖拽坐标转换、放置委托和失败回弹。
- **`GeneratorView.ts`**：作为独立节点显示固定生成器，监听点击并通过委托通知 `BoardView`；它不实现普通物品拖拽或合成。

## 核心设计

### 棋盘坐标和占位

`_items` 是按 `[col][row]` 索引的普通物品引用二维数组。列索引范围为 0–6，行索引范围为 0–8；`BoardConfig` 规定行 0 在底部、行 8 在顶部。格子位置由 `gridToLocal()` 计算；拖拽释放时，`ItemView` 将触点转换为容器本地坐标，再由 `localToGrid()` 判断有效格。

坐标转换使用左闭右开的矩形范围：左右/上下区间为 `[-总尺寸/2, 总尺寸/2)`。范围外的释放不会进入移动规则，物品回到起始位置。

### 生成器和普通物品隔离

`BoardView.GENERATOR_POS` 固定为 `(0,8)`。生成器作为独立 `GeneratorView` 节点挂在 `ItemsContainer` 中，不进入 `_items`，也不写入普通物品存档。普通物品创建和拖拽规则都会拒绝生成器格。点击生成器时，`BoardView` 按列优先、列内行递增顺序查找首个空格；满盘时不创建物品。

### 移动、交换和合成

- **移动到空格：**清空原数组格，在目标格记录物品，更新 `ItemView` 的坐标和节点位置。
- **合成：**仅当类型相同、等级相同且等级小于 12 时允许。目标物品升一级，来源物品从数组移除并请求销毁。
- **交换：**占用目标格不满足合成条件时交换两件物品的数组位置和坐标。因此两件 12 级同类物品不会合成为 13 级，而会走交换分支。
- **失败/越界：**移动委托拒绝操作后，`ItemView` 将物品放回起始位置。

### 本地存档

项目通过 `sys.localStorage` 保存 JSON，键为 `merge_board_save_v1`，版本号为 `1`。存档仅包含普通物品的 `type`、`level`、`col`、`row`。成功生成、移动到空格、交换或合成后保存；默认五件物品首次创建后也保存。固定生成器位置不序列化，每次 `onLoad()` 都会单独创建。

恢复时先建立棋盘与生成器，再解析并校验存档。校验包含版本、数组、支持的物品类型 `clothes`、整数等级范围、坐标范围、重复坐标和生成器格冲突。有效存档恢复成功后，`onLoad()` 提前返回，不再创建默认五件物品。

损坏或无效存档、读取失败以及恢复创建失败会走默认棋盘回退。恢复创建返回 `null` 或抛出异常时，当前代码会清理 `ItemsContainer` 中识别出的普通物品节点、保留生成器、重建空的 7×9 `_items`，再由 `onLoad()` 创建默认五件并尝试保存。该异常路径尚未通过故障注入实测。Cocos 节点 `destroy()` 延迟到当前帧结束，清理会先尝试停用节点；极端清理 API 异常下仍可能有节点未被成功移除，见[边界情况说明](docs/EDGE_CASES.md)。

## 已知限制与验证状态

- TypeScript 编译和类型检查尚未验证；项目 `package.json` 未提供 npm 脚本。
- `createItem()` 返回 `null`、创建中抛出异常、存储读写异常等恢复故障路径尚未注入测试。
- 生成、移动、交换、合成后分别保存并重启的独立验收仍有缺口；目前只有用户报告的整体关闭/重启恢复结果。
- 本地存档依赖运行环境的存储上下文；更换浏览器配置文件、origin、无痕会话或清除站点数据后，原存档可能不可用。
- 最高等级同级交换、精确棋盘边缘坐标、损坏/非法存档回退尚未专项实测。
- 移动或交换后物品节点名称中的初始坐标不会更新；逻辑位置和存档使用 `ItemView` 字段，不依赖节点名，但调试层级中的名字可能过时。
- `createItem()` 本身不校验传入的物品类型和等级；当前恢复入口会校验存档数据，项目内生成/默认创建使用固定合法参数。后续新增创建入口时应重新审查。
- 更完整的边界与验证限制以[边界情况说明](docs/EDGE_CASES.md)为准。

项目包含人工验证结果，但没有声称具备或通过完整自动化测试。`HANDOFF.md` 和 `AI_MENTOR_HANDOFF.md` 保留阶段接力信息，部分进度描述可能早于当前实现；如与源码、本文验证状态或更新的用户测试结果不一致，应以实际源码和最新测试证据为准。

## 进阶开发路线图

以下是 v1.0.0 基础版本之后的计划迭代顺序。版本号是规划建议，不代表对应功能已实现、版本已发布或已创建 tag/Release。当前六项状态均为**计划开发**。

| 计划版本 | 需求 | 目标 | 主要验收标准 | 当前状态 |
|---|---|---|---|---|
| v1.1 | 手感反馈 | 提升拖拽、合成和产出的即时视觉反馈。 | 拖拽时目标格高亮；可合成与不可合成目标提示有区别；合成和生成均有明确动画；原有移动规则保持正确。 | 计划开发 |
| v1.1 | 锁定格 | 支持初始不可用格，并通过相邻合成解锁。 | 锁定格不可放置普通物品；相邻格发生符合规则的合成后解锁；解锁状态存档并在重启后恢复。 | 计划开发 |
| v1.2 | 配置表驱动 | 将物品类型、等级、名称、图标和生成权重从业务逻辑迁移到配置数据。 | 配置可加载并校验；物品显示、合成链和生成权重由配置提供；新增物品时不需改业务代码。 | 计划开发 |
| v1.3 | 多条合成链 | 扩展为至少三条可区分的物品合成链，生成器按权重产出不同类型。 | 至少三种类型可独立合成；生成结果符合配置权重；不同类型不会错误合成；存档能保留各链物品类型。 | 计划开发 |
| v1.4 | 生成器体力 | 给生成器加入消耗和随时间恢复的体力，并实时呈现。 | 每次成功产出消耗 1 点；体力按设定规则随时间恢复且不超过上限；界面数值及时更新，重启后状态符合规则。 | 计划开发 |
| v1.5 | 撤销 | 支持撤销上一步移动、合成、交换或产出，并保持存档一致。 | 每类操作均可恢复操作前物品、位置和等级；撤销后 `_items`、节点和存档一致；边界失败操作不产生错误撤销记录。 | 计划开发 |

路线顺序先完善交互反馈和锁定格，再建立配置驱动的数据基础，然后扩展多合成链；体力依赖生成器状态，撤销需覆盖并同步所有操作状态，因此安排在其后。实际版本范围可在各迭代开始前根据实现结果调整。
